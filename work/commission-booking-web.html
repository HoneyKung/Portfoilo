Commission Booking Web

A two-sided booking site where artists list their packages and clients order. It carries a commission from the order all the way to confirmed delivery.

In short: A course project for a team of 3. As team lead I designed every screen in Figma and wrote part of the code. Built in late 2025.

When
Late 2025
Team / role
Team lead, team of 3 (course project): all design in Figma and part of the code
Tools
Figma · Node.js / Express · MySQL
Status
course project

Problem

A commission passes through many steps between an artist and a client: listing, ordering, pricing, paying, delivering and confirming. The project: one site that carries the whole flow for both sides.

What I decided

  • Design first, alone. I designed every screen myself in Figma before building.
  • Two roles on one site. Artists list packages and their portfolio, and clients browse and order.
  • Price after the order. The flow runs order → the artist sets the price → payment (simulated) → delivery → the client confirms.
  • Let the artist assess and quote. Drawing isn’t like other products: the price has to be agreed and assessed per job. Some clients bring a character with a lot of detail, some order just the character, some want a background too. So the artist sets the price after seeing the order.

Result

Built as a course project in late 2025 on Node.js / Express with a MySQL database, following the flow above.

My role and collaboration

I was team lead, did all the design in Figma alone and wrote part of the code myself. My teammates developed the rest of the code with AI assistance.
